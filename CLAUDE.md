# Aerostorm Racing Website — Project Brief

Student-led F1-in-Schools/STEM racing team site. Static HTML pages, Tailwind CSS via CDN, no build step. Originally scaffolded through a no-code AI site builder (see `/_sdk/element_sdk.js`, `/_sdk/data_sdk.js` refs and Cloudflare snippet in HTML `<head>`/footer) — the live GitHub connection lives on that platform's side, not in this local folder, so treat `git remote` as needing to be (re)established, not assumed.

## Design system (do not change unless asked — user chose "cleanup + automation, not a visual redesign")
- Colors: base `#000000`/`#0a0a0a`/`#111111`, card surface `#1e1e1e`, borders `#2c2c2c`/`#1e1e1e`, body text `#e8e8e8`, muted grays `#636363`→`#bababa`, signature accent (champagne/gold) `#e0d2b3` with secondary shade `#d0bd92`. Sponsor tiers: gold `#b8860b`/`#ffd700`, silver `#71706e`/`#c0c0c0`, bronze `#8b5a2b`/`#cd7f32`.
- Fonts (Google Fonts, loaded per-page): **Outfit** (`.font-heading`, body/headings), **Space Mono** (`.font-mono`, labels/eyebrow text), **MuseoModerno** (`.font-racing`, the stylized "racing"/"updates"/"engineering" wordmark next to the logo).
- Icons: Lucide (`lucide.createIcons()` call required after any dynamic DOM insertion).
- Logo: `aerostormLogoNoBG.png` (nav/hero, transparent), `aerostormLogoFinal.png` (og:image meta only — **regenerated this session**: the file used to be a 3240×4050 portrait canvas with the logo tiny and off-center, which social-preview crawlers (WhatsApp etc.) render badly or drop entirely; it's now a proper 1200×630 landscape OG image, logo centered on black. `og:image:width`/`height`/`type` meta tags added alongside it on all 5 pages that have og tags. If this ever needs regenerating again (new logo, different crop), the pattern was: PIL, `getbbox()` on a lightness threshold to find the tight content box, crop with small padding, resize to a fixed width, paste centered onto a new 1200×630 black canvas. **Note**: WhatsApp/Meta's link-preview cache is sticky per-URL — after deploying an og:image fix, an already-shared link may keep showing the old preview for a while; there's no code-side fix for that, it's crawler-side caching.

Session expiry now goes through this same helper (`_now_iso(SESSION_MAX_AGE_SECONDS)`) instead of a separate inline UTC computation that used to exist — **don't reintroduce a second time-source**, every timestamp in the DB must come from `_now_iso()` so string comparisons (`expires_at < _now_iso()`) stay valid. ## Deployment (live, not just local anymore)
The site is **actually deployed and publicly reachable** — this is no longer local-only.
- **Where**: an Ubuntu 22 LXC container (Proxmox host `alphahome`, container `knowledgecrate-website`, LAN IP `192.168.1.245`) that the user already runs several other sites on (`knowledgecrate.in`, `stratoflux.in`, etc.). The user reaches it via `ssh` from this Windows machine, but **only while on their home WiFi** — no port-forwarded SSH or VPN, so it's unreachable from outside the house or from this assistant's tools unless the user is physically home. Confirm reachability (`ping 192.168.1.245`) before assuming a live session can touch it.
- **Repo on the server**: `git clone`d at `/var/www/aerostorm`, owned by `www-data`. Deploying an update = `git pull` there (as `www-data` or with a subsequent `chown`) + `systemctl restart aerostorm`. There's no CI/CD — updates are manual, pushed from this local repo to GitHub first, then pulled on the server. **Suspected broken**: the admin server writes content JSON files (`pages-content.json` etc.) directly to this same git-tracked working directory, which likely gives the server local modifications that block/partially-block future `git pull`s on those files — see Pending work #1 for the live investigation. Don't assume "I pushed to GitHub" means the user can see it; confirm a deploy actually landed (e.g. `curl` the live page and check for the specific change) before treating it as done, given this is an open, unresolved suspicion.
- **Process**: runs as a systemd service, `/etc/systemd/system/aerostorm.service` — `User=www-data`, `Environment=PORT=8000` and `Environment=HOST=127.0.0.1` (binds loopback-only; nginx is the sole public entry point), `Restart=on-failure`. `systemctl status/restart/enable aerostorm` to manage it.
- **Public routing**: Cloudflare Tunnel (dashboard-managed, not a local `config.yml`) — the tunnel forwards every hostname on this box (`knowledgecrate.in`, `stratoflux.in`, `aerostorm.knowledgecrate.in`, etc.) to `http://localhost:80`, and nginx does the actual per-hostname routing via `server_name` in `/etc/nginx/sites-enabled/*`. Aerostorm's block is `/etc/nginx/sites-enabled/aerostorm`, reverse-proxying everything to `127.0.0.1:8000`, with `limit_req_zone` rate limits on `/api/admin/login` (5r/m) and `/api/contact-submit` (10r/m) specifically — the two most abuse-prone public routes. **Always `nginx -t` before `systemctl reload nginx`** on this box — it's shared config serving multiple other live sites, a syntax error would take all of them down, not just Aerostorm.
- **Current domain**: `aerostorm.knowledgecrate.in` — explicitly temporary. The user's team hasn't finalized a real domain yet (`aerostorm.in` or similar was mentioned as likely). Swapping later is cheap: point the new domain's DNS at the same tunnel, update `server_name` in the nginx block, done — nothing in the app code is domain-specific (no hardcoded CORS/cookie-domain/absolute-URL assumptions). Don't be surprised if a future session is asked to do exactly this swap.
- **GitHub Pages**: superseded by this deployment for the *live* site, per the user's explicit choice ("whole site + admin, replacing GitHub Pages"). The repo's GitHub remote (`github.com/DarkWizAdy/aerostorm`) is still the source of truth / where `git push` goes — it's just no longer what visitors actually hit.
